# Theme Engine Design System: The `color-mix` Logic

This documentation explains the technical and aesthetic reasoning behind using the CSS `color-mix()` function instead of defining static manual hex codes for every UI element.

## 1. Why `color-mix()`?

Our primary goal is to establish a **Single Source of Truth**. By utilizing `color-mix()`, we only need to define 6 base variables:
* `--bg` (Background) & `--fg` (Foreground/Text)
* `--pr` (Primary), `--sc` (Success), `--da` (Danger), `--wr` (Warning)

All supporting colors (such as borders, hover states, or inset surfaces) are **automatically calculated** based on these base values. This ensures a consistent color harmony across the application without the risk of manual hex code entry errors.

## 2. Breaking Down the Ratios

We use the `in srgb` color space for accurate digital mixing. Here is the logic behind the percentages applied:

### A. Background & Depth Logic
Visual hierarchy (depth) is created by mixing `--bg` with Black or White:

| Variable | Formula | Usage |
| :--- | :--- | :--- |
| `--bg-subtle` | `white 5%` | Creates a slightly lighter surface effect for top-level elements. |
| `--bg-overlay`| `black 15%` | Used for modals or floating elements to give a more solid, elevated feel. |
| `--bg-inset`  | `black 30%` | Creates a "sunken" or recessed effect, ideal for input fields or containers. |

### B. Border & Interactive Logic
Borders use white mixing to provide subtle but visible contrast against dark backgrounds:

* **`white 10%` (Muted):** Barely visible, used for very soft content separators.
* **`white 15%` (Default):** The standard contrast for separating major components like cards.
* **`white 20%` (Hover):** Provides visual feedback when hovering, making the element appear to "glow" or lift.

### C. Functional Colors (Alerts & Buttons)
For status colors like `--pr` (Primary) or `--sc` (Success), we mix them with `--bg` so they don't look "disconnected" from the overall theme:

* **`20% Mix` (Background):** Produces a very soft tint that remains in harmony with the main theme color.
* **`40% Mix` (Border):** Provides a defined stroke for status elements to ensure better legibility and accessibility.

## 3. Technical Advantages

1. **Maintainability:** If you want to switch from a Dark to a Light theme, you only need to change the `--bg` value. The entire system (borders, insets, subtle surfaces) will automatically adjust its brightness levels.
2. **Reduced CSS Size:** There is no need to write hundreds of lines of hex codes. The browser handles the mixing logic in real-time.
3. **Dynamic Inversion:** Since we use JavaScript to invert `--fg` based on `--bg`, the system guarantees that text will always remain legible (high contrast) regardless of the theme color chosen by the user.
